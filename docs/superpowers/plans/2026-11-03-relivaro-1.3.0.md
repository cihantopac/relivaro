# Relivaro 1.3.0 Field-Report Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the defects and blind spots that Relivaro 1.2.2 showed on two real projects (cihanca.com, Frameva v2). Ship them as `relivaro@1.3.0`.

**Architecture:** No new subsystems. The work fits the existing layers:

- `src/deps` — parsing, with errors surfaced in `src/audit.ts` and `src/release/readiness.ts`.
- `src/fs/files.ts` — file selection.
- `src/review` — verdicts, then shown in the report renderers.
- `src/intel` + `src/rules` — new detection: a web-server header parser plus project rules.
- `src/cli` — terminal output and help.

Every change gets a test. Rule changes also get a fixture with `expect:` annotations, so the detection corpus keeps precision and recall at 100%.

**Tech Stack:** TypeScript (ESM, Node ≥ 22), vitest, Biome, esbuild bundle at `plugin/dist/relivaro.mjs`, `yaml@2`.

**Spec:** two field reports, checked against the code on 2026-11-02 and 2026-11-03:

- cihanca.com — Next.js static export behind Caddy + cloudflared, offline, two runs. Evidence is in that repository, branch `next`, under `docs/verification/relivaro/`.
- Frameva v2 — pnpm 12 + Turborepo, `--online`. Report: `/Users/cihan/Developer/frameva/docs/tool-feedback/relivaro/2026-11-02-m0-scaffold-audit.md`.

## Global Constraints

- The user-facing language of code, docs, CLI output and changelog is English. TR strings exist only in `src/report/html-i18n.ts`.
- No new runtime dependencies. `package.json` `dependencies` stays empty, and the bundle stays self-contained.
- Read-only and offline by default. No new rule may execute project code or touch the network.
- The report's security model is unchanged: CSP `default-src 'none'`, `textContent` only, `<` escaped in the payload.
- Biome must be clean: `npm run lint`.
- The detection corpus must stay at precision and recall 100%: `npm run bench` and the detection tests.
- Any `src/` change requires a rebuilt `plugin/dist/relivaro.mjs`. CI `check:dist` fails otherwise.
- Version `1.3.0` goes in `package.json`, `package-lock.json`, `plugin/.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `src/core/version.ts`, `docs/CLI.md` and `plugin/skills/relivaro/references/cli.md`.
- Never read `.env` or other secrets in any repository. Other repositories (cihanca.com, frameva) are read-only references.

## Review Focus

1. **Malformed or partial pnpm documents.** A two-document file whose second document is truncated must surface a parse limitation. It must not silently fall back to the env document's packages. Test in Task 1.
2. **A user's own HTML or Markdown that merely mentions "Relivaro".** It must still be analysed. Report detection must match exact generator markers, never the bare word. Test in Task 2.
3. **An `accepted` verdict on a finding whose fingerprint changed.** It must not carry over, which is the existing fingerprint rule. Test in Task 3.
4. **A CSP set only by a `<meta http-equiv>` tag in a static HTML page.** No `web-missing-csp` finding when the served HTML already declares one. Test in Task 4.
5. **A Next.js config that sets `output` from an env var** (`output: process.env.X`). It must not be treated as a static export. Only a literal `'export'` counts. Test in Task 5.
