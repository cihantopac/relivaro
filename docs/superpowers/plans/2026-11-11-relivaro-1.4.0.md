# Relivaro 1.4.0 Correctness Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove every false positive and every silent blind spot that the Frameva field reports found in Relivaro 1.3.0, close the false negatives that fall inside existing rules, clear the deferred minors of the 1.3.0 review, and ship the result as `relivaro@1.4.0`.

**Release order:** This is release 1 of 3.
- 1.4.0 (this plan): correctness.
- 1.5.0: integration and hosted scanning. Plan: `docs/superpowers/plans/2026-11-11-relivaro-1.5.0.md`.
- 1.6.0: new rule families. Plan: `docs/superpowers/plans/2026-11-11-relivaro-1.6.0.md`.

The user's priority is "hatasız olması", which means no wrong findings and no silent gaps. That is why correctness ships first.

**Architecture:** No new subsystem. One new module:
- `src/fs/ancestors.ts` reads a fixed set of metadata files in the directories above the audit root.
- It exists because three false positives (RELIVARO-020, RELIVARO-021 and the "no test commands" limitation) come from Relivaro not seeing the monorepo root when it audits a single package.

Everything else is a narrow change in the rule or the file-selection code that owns the defect. Each false positive gets a negative case in a fixture: any finding that has no `expect:` annotation fails `tests/integration/detection.test.ts`, so a fixture pins the fix.

**Tech Stack:** TypeScript (ESM, Node ≥ 22), vitest, Biome, tree-sitter (`src/parse/ast.ts`), esbuild bundle at `plugin/dist/relivaro.mjs`.

**Rulings already made (planner):**
- **Placeholder-looking keys stay suppressed.** `isSyntheticSample` is deliberate false-positive protection, and Frameva planted those keys on purpose. Cost if wrong: a real key that happens to contain `EXAMPLE` goes unreported. That is the same as today.
- **A generic SHA-1/MD5 rule is not part of 1.4.0.** It would flag git object ids, ETags and cache keys, which goes against the release goal. Revisit in 1.6.0 only together with a purpose signal.
- **Literal union types (R3d) are out of reach.** The parser has no type information. Without a ruling a builder could invent a heuristic that guesses wrong.
- **A loop that must be sequential stays reported.** The fix is `relivaro-accept` (R5), not a heuristic.
- **Chunk loops (`i += N`) stay reported.** One query per chunk is still a query in a loop; `relivaro-accept` covers the reviewed case.

## Global Constraints

- Read-only and offline by default. `src/fs/ancestors.ts` may only read the file names in `ANCESTOR_META` (Task 1). Every other read goes through `FileSet`.
- Never read `.env` or other secrets in any repository. `frameva` and `cihanca.com` are read-only references.
- Biome clean: `npm run lint`. Typecheck clean: `npm run typecheck`.

- Any `src/` change requires a rebuilt `plugin/dist/relivaro.mjs` (`npm run build`), and `npm run check:dist` must pass. `docs/RULES.md` is regenerated by the build.

## Review Focus

1. **An ancestor directory that is not the project's workspace root.** For example, `/work/package.json` above an uploaded archive at `/work/repo`, or the user's home directory. It must be ignored unless its workspace globs include the audit root. Test in Task 1.
2. **A ternary whose branches are not both constant** (`cond ? 'FOR UPDATE' : userInput`). It must still be reported. Test in Task 3.
3. **A `relivaro-accept` comment without a reason.** It must not accept anything, and it is reported as an invalid annotation in `errors.rules`, the same way a malformed suppression is handled today. Test in Task 5.
4. **A library package with a server entry file** (`src/server.ts` calling `app.listen`). It is still a service. Test in Task 6.
5. **A symlink loop or a link to a directory that contains the link.** It must not hang the walk or count the files twice. Test in Task 8.
